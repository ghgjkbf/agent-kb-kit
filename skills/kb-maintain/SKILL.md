# kb-maintain — 知识库维护（只读体检 + 提议）

> 体检第 6 段是**优化提议**：索引与条目排序、近似冗余合并、过长条目精简。同样是只读产出，合入与删减待用户确认后才落地。

共享知识库根目录由 `KB_ROOT` 指定（默认 `<仓库>/knowledge-base`，配置见仓库 README），读写协议全文见该目录 `README.md`（权威真值，动手前先读）。写一条走 `kb-add`，读走 `knowledge-base`，本技能负责**全库体检与归位提议**。

## 铁律

- 体检脚本 `kb_audit.py` **只读**：不改文件、不动 INDEX、不删条目、不发写请求（唯一网络动作是对条目里已登记的 URL 发带超时的 HEAD/GET 探测）。
- **归位、归档、规范升格一律先提议、待用户确认**再动手（README 契约：`norms\` 升格与 README 修改需用户确认）。确认后：归位用 `kb-add` 的 `append` + 手工改 `status`，或按 README 协议移文件。
- 本技能不发明新事实：报告里每条结论都要能指回具体文件路径与行。

## 流程

1. **体检**：

   ```
   python <本技能目录>/scripts/kb_audit.py
   ```

   输出五段常规体检：索引对账（悬空指针 / 磁盘孤儿）· frontmatter 合规 · 环境依赖漂移 · 检索盲区统计 · 规范草案区。
   第 6 段是**优化提议**：排序（INDEX 是否自新到旧、状态列与 frontmatter 是否一致、同一文件是否被多行重复指向）、冗余（近似重复条目对）、精简（正文超长且集中了臃肿章节的条目）。此段仅提议，`findings` 不计入它，不改任何文件。
   加 `--no-net` 跳过 URL 探测（离线或只想看结构），`--json` 出机器可读结果。
2. **判读**（关键，别照抄脚本输出）：
   - **悬空指针**：INDEX 指向的文件不存在 → 确认是文件被移走还是路径写错，回填或删行。
   - **磁盘孤儿**：`inbox\` / `memory\{facts,projects,conversations,references}\` / `norms\` 下有文件但 INDEX 无指针 → 补一行指针（这属于索引缺陷，不是新条目）。
   - **漂移**：路径 `Test-Path=False`、URL 主机 DNS 解析失败 → 拿真实环境核对后改正文，并在该条目追加「更新记录」；**验不了（超时/拒连/HTTP 状态码）一律归不可确证，不算漂移**，不要凭猜改。
    - **盲区**：`retrieval-gaps.log` 里重复出现的查询说明知识缺口，作为下一条待写清单的依据。注意该日志目前只覆盖 memU 路；zg（zvec-grep）试行期的零命中暂无自动日志，体检时可人工抽几条 zg 查询对照。
   - **优化**（第 6 段，同样只提议）：排序——INDEX 反转处、状态列与 frontmatter 不一致、同一文件被多行重复指向；冗余——重叠度超阈值的条目对（读了再说，阈值不是判决）；精简——正文远超中位数且臃肿集中在某几节的条目（带「更新记录」的只折叠，不改写历史）。
3. **归位**（`inbox\` → `memory\<分类>\`）：按 README 判 `type`，移文件、改 `status: curated`、在 INDEX 把状态列改成 `curated`。
4. **归档**：过期或被推翻的条目移 `archive\`，文件头加 `archived-reason:`，INDEX 状态列改 `archived`（不删除）。
   - **合并**：近似冗余对先把较薄的一侧增量并入权威条目（内容不丢），原件移 `archive\` 并写 `archived-reason`；重复指向的 INDEX 行删多余那行。
   - **精简**：只动真正的臃肿——去重、删已被后续条目推翻的旧结论、压缩叙述；不删「更新时间线」与审计金信息。
5. **规范升格**：`norms\inbox-drafts\` 的草案只在用户明确确认后升格到 `norms\`，INDEX 状态 `active`。
6. **对账**：收尾跑

   ```
   python <仓库>/sync/sync_knowledge_base.py --if-changed
   ```

   批量归位/归档后在 INDEX 与正文都改完再跑，未对账的检索命中的是旧快照。
   再补一次 zg 索引刷新（归位/归档移动了文件，zg 不刷新会命中旧路径；增量约 1 秒，zg 未装则跳过）：

   ```
   cd <知识库根>; zg index
   ```
7. **出报告**：写一条 `inbox\<日期>-kb维护报告.md`（用 `kb-add`，`type: conversation`），四栏：本次改了什么（旧→新）、体检计分（dangling / orphan / drifted / 不可确证）、盲区回填、**待你决策**（归档清单、规范升格清单）。没有实际改动就只报体检结论，别为凑报告造条目。

## 脚本

`scripts\kb_audit.py`，纯标准库，源码全 ASCII（个别 Windows 环境的 `python` 按 ANSI 读源码）。

| 参数 | 用途 |
|---|---|
| 无参 | 跑全部检查，人类可读输出 |
| `--json` | 机器可读（供别处消费） |
| `--no-net` | 跳过 URL 探测，只做本地检查 |
| `--timeout S` | URL 探测超时，默认 6 秒 |
| `--max-urls N` | 本次最多探测的 URL 数，默认 20（限流，避免扫全库卡住） |
| `--fail-on-findings` | 有悬空/孤儿/漂移时退出码 1，其余仍为 0 |
| `--root P` | 覆盖 KB 根（默认 `KB_ROOT` 环境变量 > `<仓库>/knowledge-base`） |

判读口径：

- `dangling` = INDEX 指针指向缺失文件；`orphan` = 该进 INDEX 的文件没进；
- `drifted` 只含两类硬证：路径不存在（父目录仍在）与 URL 主机 DNS 解析失败；
- `http status` 单列：任何 HTTP 应答（含 401/403/404/5xx）都**不算漂移**。API 路径与只收 POST 的端点对 GET 回 404 是正常的，拿不到 GET 处理器不等于资源消失；
- `unverifiable-cheaply` = 超时、连接被拒——**不等于漂移**，列出来供人工抽查；
- 路径里含 `<` `>` `%` `*` 的（占位符样板）、双反斜杠转义写法（JSON/CLI 示例），以及带「已清除 / 已失效 / 不存在 / 断链 / 卸载 / 残留 / 空壳」等历史标记的行，都不参与漂移判定：那些路径本就该不存在。
- 每条结果带「文件:行号」，便于回原条目核对。
